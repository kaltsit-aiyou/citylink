# CityLink 城邻云｜系统架构设计

版本：V0.2  
状态：草稿  
依据：PRD V0.2 的 MVP-A 范围

## 1. 设计目标

第一版要支持用户注册登录、浏览门店、发布和互动笔记、关注用户，以及参与兴趣圈子。系统先采用模块化单体：所有业务运行在一个后端应用中，各模块按职责组织。

第一轮通过接口工具演示 PRD 中的验收场景。客户端展示形式在后续确定。

## 2. 整体结构

客户端或接口工具通过 HTTP 请求访问后端。后端接收请求、验证身份、执行相应业务规则，然后读取或写入 MySQL，并返回 JSON 结果。

后端计划使用 Java 17、Spring Boot 4.1.2、Maven、MyBatis 和 MySQL。登录与接口访问控制计划使用 Spring Security 和 JWT。具体依赖版本在创建工程时确定。

在 IDEA 中创建工程时核对项目 JDK 为 17。IDEA 已有可用的 Maven；MySQL 等依赖环境按开发进度准备。

## 3. 业务模块

用户模块负责注册、登录和个人资料。

商户模块负责门店分类、列表和详情查询。MVP-A 的门店数据由项目预先准备，不提供商户自行入驻和维护功能。

笔记模块负责发布、浏览、修改和删除笔记，以及图片关联、点赞、收藏和评论。

关注模块负责关注关系、关注列表和按时间展示的关注用户笔记。

圈子模块负责圈子信息、成员关系、圈子讨论及创建者的基础管理操作。

每个模块内部区分三类职责：接口层接收请求并返回结果；业务层执行规则；数据访问层读写数据库。跨模块调用由业务层完成。

## 4. 权限规则

未登录用户可以浏览公开的门店、笔记和圈子内容。登录用户可以发布内容、互动、关注和加入圈子。笔记只有作者可以修改或删除。圈子讨论只允许圈子成员发布；圈子的基础管理操作只允许创建者执行。

这些规则在后端检查，不能只依赖客户端界面隐藏按钮。

## 5. 数据库草图

以下是 MVP-A 预计需要的主要数据，不是最终建表语句：

- 用户、用户资料和登录所需信息。
- 门店分类、门店及其地址信息。
- 笔记、笔记图片、评论、点赞和收藏关系。
- 用户之间的关注关系。
- 圈子、圈子成员、圈子讨论和讨论评论。

一个用户可以发布多篇笔记；一篇笔记可以关联一家门店。关注关系连接两个用户。圈子成员关系连接用户与圈子，并记录成员在圈子中的身份。

用户名应保持唯一。同一用户对同一笔记的点赞、收藏，以及同一圈子的成员关系，都应避免重复记录。具体字段、索引和表名将在数据库设计时确定。

## 6. 接口范围

第一版需要账户、门店、笔记、关注和圈子五组接口。每组接口分别支持 PRD 所列的查询或操作。接口路径、请求字段、返回格式和错误码将在接口设计时统一确定。

## 7. 待确定事项

笔记图片在开发阶段的存储方式、客户端展示形式、门店示例数据的准备方式，以及 MySQL 的安装和版本，仍需进一步确定。Redis、搜索引擎、消息队列和微服务组件不进入 MVP-A 的基础工程。
