# CityLink 城邻云｜系统架构设计

- 版本：V0.4
- 状态：草稿（账户页面与后端已联通，其他模块待实现）
- 依据：PRD V0.2 的 MVP-A 范围

## 1. 设计目标

MVP-A 计划支持用户注册登录、浏览门店、发布和互动笔记、关注用户，以及参与兴趣圈子。系统采用模块化单体：业务运行在一个后端应用中，各模块按职责组织。

当前阶段已实现账户后端接口及注册、登录、个人资料页面，可以通过浏览器完成账户操作。门店、笔记、关注和圈子页面尚未实现。

## 2. 整体结构

客户端或接口工具通过 HTTP 请求访问后端。后端接收请求、验证身份、执行业务规则，使用 MyBatis 读取或写入 MySQL，并返回 JSON。

当前后端使用 Java 17、Spring Boot 4.1.2、Maven、MyBatis 和 MySQL。账户模块使用 Spring Security 控制访问，使用 BCrypt 保存密码摘要，使用 JWT 表示登录身份。JWT 有效期为 7200 秒；后端不使用登录会话。

数据库密码和 JWT 签名密钥从环境变量读取，不保存在 Git 仓库中。

账户前端使用 HTML、CSS 和原生 JavaScript，放在 `backend/src/main/resources/static` 中，由 Spring Boot 与接口一起提供服务。浏览器通过 `fetch` 调用同源的 `/api` 接口，无需另外启动前端服务器。文件说明和运行步骤见 `docs/FRONTEND.md`。

## 3. 业务模块

账户模块已实现注册、登录、查看自己的资料和修改自己的昵称、头像地址。代码分为接口层（Controller）、业务层（UserService）和数据访问层（UserMapper）。

商户模块计划负责门店分类、列表和详情查询。MVP-A 的门店数据由项目预先准备，不提供商户自行入驻和维护功能。

笔记模块计划负责发布、浏览、修改和删除笔记，以及图片关联、点赞、收藏和评论。

关注模块计划负责关注关系、关注列表和按时间展示的关注用户笔记。

圈子模块计划负责圈子信息、成员关系、圈子讨论及创建者的基础管理操作。

## 4. 权限规则

首页和 `/assets/**` 静态资源允许匿名读取，注册、登录接口允许未登录访问。查看或修改自己的资料需要在请求头中携带有效的 Bearer JWT；后端从令牌中取得用户 ID，只操作该用户的资料。

后续计划允许未登录用户浏览公开的门店、笔记和圈子内容；发布内容、互动、关注和加入圈子需要登录。笔记修改和删除、圈子讨论与管理等权限将在对应模块实现时检查。

## 5. 数据库

账户模块已使用 `app_user` 表，保存用户名、密码摘要、昵称、头像地址及创建、更新时间。用户名有唯一约束。实际建表语句见 `backend/sql/001_account.sql`。

门店、笔记、关注和圈子的数据表仍处于设计阶段，详见 `docs/DATABASE.md`。

## 6. 已实现的账户接口

| 方法与路径 | 用途 | 成功状态 |
| --- | --- | --- |
| `POST /api/auth/register` | 注册并返回不含密码摘要的用户资料 | 201 |
| `POST /api/auth/login` | 登录并返回 Bearer JWT | 200 |
| `GET /api/users/me` | 查看当前登录用户资料 | 200 |
| `PUT /api/users/me` | 修改当前登录用户的昵称、头像地址 | 200 |

注册参数不合法返回 400，用户名重复返回 409；用户名或密码错误、未携带有效令牌访问受保护接口返回 401。注册用户名限 3～50 个英文字母、数字或下划线；密码限 8～64 个字符，且不能超过 72 个 UTF-8 字节。

账户页面使用当前标签页的 `sessionStorage` 保存令牌，刷新后重新读取资料，退出时删除令牌并清空显示资料。令牌到期或接口返回 401 时要求重新登录。目前没有服务端令牌撤销接口，已复制的令牌在到期前仍可能有效。

## 7. 待确定事项

笔记图片的存储方式、后续业务页面的展示方式和门店示例数据的准备方式仍需确定。门店、笔记、关注和圈子的具体接口、字段和权限规则将在实现对应模块时核对。Redis、搜索引擎、消息队列和微服务组件不进入 MVP-A 的基础工程。
