# CityLink 城邻云｜数据库设计

版本：V0.1
依据：产品需求文档 V0.2、系统架构设计 V0.2
状态：草稿  
范围：MVP-A

## 1. 设计目标

数据库需要支持账户、门店发现、探店笔记、关注关系和兴趣圈子。以下先确定主要数据及关联；字段类型、建表语句和索引将在创建工程前进一步核对。

每张主要数据表使用独立的 `id` 标识记录。保存创建时间；需要修改的数据也保存更新时间。

## 2. 用户与门店

`app_user` 保存用户的用户名、密码摘要、昵称、头像地址和创建时间。用户名不能重复，密码不以明文保存。

`merchant_category` 保存门店分类名称。`merchant` 保存门店名称、所属分类、城市、地址和简介。MVP-A 的门店资料由项目预先准备，不设计商户自行入驻所需的审核数据。

## 3. 笔记与互动

`note` 保存作者、标题、正文、可选的关联门店、创建时间和状态。一个用户可以发布多篇笔记；一篇笔记最多关联一家门店。

`note_image` 保存笔记与图片地址的关系，并记录图片显示顺序。一篇笔记可以没有图片，也可以有多张图片。

`note_comment` 保存评论所属笔记、评论作者、内容和创建时间。

`note_like` 与 `note_favorite` 分别保存用户对笔记的点赞和收藏关系。同一用户对同一笔记，在每张关系表中最多有一条有效记录。

## 4. 关注关系

`user_follow` 保存关注者、被关注者和关注时间。同一对用户不能重复关注，用户也不能关注自己。关注流根据这张关系表查出被关注用户的笔记，并按发布时间展示。

## 5. 兴趣圈子

`interest_circle` 保存圈子名称、简介、创建者和创建时间。

`circle_member` 保存圈子、用户、圈内身份和加入时间。同一用户在同一圈子只保留一条成员关系。创建圈子时，创建者同时成为该圈成员，并具有创建者身份。

`circle_post` 保存所属圈子、作者、内容和创建时间。`circle_post_comment` 保存圈子讨论的评论。发布讨论前，后端需要确认作者是该圈成员。

## 6. 主要约束与查询

用户名需要唯一约束。点赞、收藏、关注和圈子成员关系需要防止重复的约束。笔记、评论、关注和圈子讨论都要能根据所属用户或所属内容查询。

门店列表需要支持按分类查询。笔记列表、关注流和圈子讨论需要支持按时间分页。具体索引根据最终查询接口确定。

## 7. 待确定事项

笔记图片的实际存储位置和地址格式、内容删除后的数据保留规则，以及圈子创建者退出时的处理方式，仍需在接口和实现设计中确定。
