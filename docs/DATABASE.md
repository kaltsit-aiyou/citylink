# CityLink 城邻云｜数据库设计

- 版本：V0.2
- 依据：产品需求文档 V0.2、系统架构设计 V0.3
- 状态：草稿（账户表已实现，其他表待设计）
- 范围：MVP-A

## 1. 设计目标与进度

数据库计划支持账户、门店发现、探店笔记、关注关系和兴趣圈子。当前只实现账户所需的 `app_user` 表；下文其他表仍是设计草图，不代表已经建表。

主要数据表计划使用独立的 `id` 标识记录，并按需要保存创建和更新时间。

## 2. 已实现的账户表

建表脚本位于 `backend/sql/001_account.sql`，使用 `citylink` 数据库。脚本中的 `IF NOT EXISTS` 可以避免重复创建已有数据库或表，但不会修改已有表的结构。

| 字段 | 类型 | 作用 |
| --- | --- | --- |
| `id` | `BIGINT`，主键、自增 | 用户 ID |
| `username` | `VARCHAR(50)`，非空 | 登录用户名 |
| `password_hash` | `VARCHAR(255)`，非空 | BCrypt 密码摘要，不保存明文密码 |
| `nickname` | `VARCHAR(50)`，非空 | 显示昵称；注册时初始值为用户名 |
| `avatar_url` | `VARCHAR(512)`，可为空 | 头像地址 |
| `created_at` | `DATETIME`，非空 | 创建时间，默认当前时间 |
| `updated_at` | `DATETIME`，非空 | 更新时间，修改记录时自动更新 |

`uk_app_user_username` 是用户名唯一索引，用于防止重复注册。后端通过 `citylink_app` 数据库账号连接 MySQL；账号密码从 `CITYLINK_DB_PASSWORD` 环境变量读取。

## 3. 计划中的门店数据

`merchant_category` 计划保存门店分类名称。`merchant` 计划保存门店名称、所属分类、城市、地址和简介。MVP-A 的门店资料由项目预先准备，不设计商户自行入驻所需的审核数据。

## 4. 计划中的笔记与互动数据

`note` 计划保存作者、标题、正文、可选的关联门店、创建时间和状态。一个用户可以发布多篇笔记；一篇笔记最多关联一家门店。

`note_image` 计划保存笔记与图片地址的关系，并记录图片显示顺序。一篇笔记可以没有图片，也可以有多张图片。

`note_comment` 计划保存评论所属笔记、评论作者、内容和创建时间。

`note_like` 与 `note_favorite` 计划分别保存点赞和收藏关系。同一用户对同一笔记不能重复点赞或收藏。

## 5. 计划中的关注与圈子数据

`user_follow` 计划保存关注者、被关注者和关注时间。同一对用户不能重复关注，用户也不能关注自己。关注流按笔记发布时间展示。

`interest_circle` 计划保存圈子名称、简介、创建者和创建时间。`circle_member` 计划保存圈子、用户、圈内身份和加入时间，同一用户在同一圈子只保留一条成员关系。

`circle_post` 计划保存圈子讨论的作者、内容和创建时间；`circle_post_comment` 计划保存讨论评论。发布讨论前，后端需要确认作者是圈子成员。

## 6. 后续约束与查询

点赞、收藏、关注和圈子成员关系需要防止重复。门店列表需要支持按分类查询；笔记列表、关注流和圈子讨论需要支持按时间分页。具体字段和索引将在实现相应模块时确定。

## 7. 待确定事项

笔记图片的实际存储位置和地址格式、内容删除后的数据保留规则，以及圈子创建者退出时的处理方式，仍需在对应模块设计时确定。
